A deterministic auditor for carbon credit registries, detecting double-counting failure modes and anchoring audit reports to a smart contract. Working prototype for the IEEE ClimateChain "Carbon Markets & Emissions Transparency" track (13/13 tests; static verification dashboard in `dashboard.html`; testnet deployment kit in `scripts/` — preflight-proven, awaiting only a throwaway testnet wallet).

## What It Does

The auditor ingests a carbon credit registry dataset (JSON), runs deterministic detectors for four key failure modes, and produces a structured audit report where every finding carries its evidence records. Clean datasets return zero substantiated findings and explain why suspicious patterns are legitimate (near-misses).

The report's canonical form (deterministic JSON) is hashed with SHA-256, then committed to a smart contract that records the hash, committer, and timestamp immutably. This anchoring proves that a specific audit result existed at a specific moment, and subsequent tampering will be detected.

## Key Features

- **Deterministic Detectors:** No randomness, no timestamps inside findings. Same records → same report hash, always.
- **Evidence-Based Findings:** Each finding quotes the actual records and events that prove it, not an abstract summary.
- **Near-Miss Explanation:** Clean datasets surface suspicious-but-legitimate patterns (e.g., multiple credits from the same project) and explain why they are not findings.
- **Anchor Design:** A LOCAL FIXTURE simulates the contract semantics for development and testing. Deployment target is a testnet (e.g., Sepolia, Mumbai).
- **Verification Dashboard:** `dashboard.html` (generated by `scripts/make_dashboard.py`) renders batch history, findings with their evidence, near-misses, the anchor receipt, and a build-time tamper demonstration — and lets anyone recompute the report's canonical SHA-256 in the browser and compare it with the anchored hash. The in-browser canonicalizer is verified byte-identical to the Python canonical form.
- **Zero Dependencies:** The package uses only Python standard library (hashlib, json, csv, dataclasses). Tests use pytest.

## Architecture

### Detection

Four deterministic detectors:

1. **Duplicate Serial** — Two distinct credit records with the same serial string.
2. **Double Retirement** — A single credit with 2+ "retired" events.
3. **Retired-Then-Traded** — A "transferred" event that occurs after a "retired" event on the same credit.
4. **Quantity Mismatch** — Retired + transferred-out quantities exceed the issued quantity.

Each detector returns a Finding with:
- `kind`: the error type
- `serials`: affected credit serials
- `evidence`: list of dicts quoting the actual record data and events
- `explanation`: human-readable summary

### Audit Report

An audit report is a deterministic dict:

```json
{
  "batch_id": "uuid-hex-string",
  "generated_from": 42,
  "findings": [
    {
      "kind": "duplicate_serial",
      "serials": ["SERIAL-001"],
      "evidence": [ ... ],
      "explanation": "..."
    }
  ],
  "finding_counts": {
    "duplicate_serial": 1,
    "double_retirement": 0,
    "retired_then_traded": 0,
    "quantity_mismatch": 0
  },
  "near_misses": [
    {
      "pattern": "multiple_credits_same_project_vintage",
      "serials": ["SERIAL-002", "SERIAL-003"],
      "why_not_a_finding": "Multiple credits from the same project and vintage year..."
    }
  ],
  "records_checked": 42,
  "clean": false
}
```

The canonical form (used for hashing) **excludes `batch_id`** to ensure determinism across runs.

### Anchoring

The `LocalChainFixture` class simulates the contract semantics:

- Maintains an in-memory commitment registry.
- On `commit(hash)`: increments a block counter, derives a deterministic timestamp (1,760,000,000 + block), stores the commitment, returns a receipt.
- Is idempotent: committing the same hash twice returns the original receipt.
- On `verify(hash)`: returns whether the hash is in the registry.
- On `verify_report(report)`: recomputes the hash from the report and checks if it is anchored. **If the report is tampered** (any finding edited), the recomputed hash will differ from the committed one, so `match=False`.

**Local Fixture Label:** This is NOT a blockchain. It is a deterministic simulator for development and testing, designed to be replaced by a real testnet deployment with the same interface.

The real contract (`contracts/AuditAnchor.sol`) is a minimal Solidity contract (^0.8.20) that:
- Maps report hashes (bytes32) to commitment timestamps and committers.
- Emits an `Anchored` event on commit.
- Provides a view function to verify commitments.
- No tokens, no funds, no financial operations.

## Running the Auditor

### Setup

```bash
# Create and activate virtual environment (if needed)
python3.12 -m venv .venv
source .venv/bin/activate

# Install test dependencies
pip install -r requirements.txt
```

### Run Tests

```bash
.venv/bin/python -m pytest tests/ -q
```

All tests should pass.

### Usage Example

```python
from registry_auditor import run_audit, audit_and_anchor
from registry_auditor.ingest import load_dataset
from registry_auditor.anchor import LocalChainFixture

# Load dataset
records = load_dataset("fixtures/registry_fixture.json")

# Run audit
report = run_audit(records)
print(f"Clean: {report['clean']}")
print(f"Findings: {report['finding_counts']}")

# Anchor to chain
chain = LocalChainFixture()
result = audit_and_anchor(records, chain)
print(f"Anchored at block {result['receipt']['block']}")
print(f"Verification match: {result['verification']['match']}")
```

## Fixture Data

The file `fixtures/registry_fixture.json` is a SYNTHETIC dataset designed for development and testing. It is clearly labeled with `"_fixture": "SYNTHETIC fixture data..."` at the top level and is **not a real carbon registry export**.

The fixture contains:
- Two records with the same serial (duplicate serial error).
- One credit with two retired events (double retirement error).
- One credit transferred after retirement (retired-then-traded error).
- One credit with quantity mismatch (retired + transferred > issued).
- Three or more fully clean credits, including patterns that match near-miss categories:
  - Two credits sharing project+vintage but distinct serials.
  - A credit cleanly fully retired for its exact quantity.
  - A credit transferred multiple times before final retirement.

## Determinism Guarantees

- Report hash depends only on records, not on batch_id or runtime state.
- Timestamps in findings are NOT allowed; timestamps exist only in the receipt (after anchoring).
- Detectors are pure functions with no side effects.
- JSON serialization uses deterministic ordering (sort_keys=True, separators=(",", ":")).
